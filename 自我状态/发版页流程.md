# 「道」两页发版 SOP（2026-11-26 学会并跑通）

## 一句话
发版不只是编包：**两页版本号 + 直链 + 字节数必须一起改，再发布、查到 finished，最后写三本账**。漏一项就会出现「页面说 v62、实际包里 v147」这种不一致。

## 两个页面固定不变
| 用途 | app_id | 线上地址 | 源码 |
|---|---|---|---|
| 下载页 | `app_17hnj8acgs2` | https://4mf81m04wehh3.doubao.link/app/app_17hnj8acgs2 | `F:\Daodao\引导页_src\index.html` |
| 版本清单 | `app_17hpue26uuw` | https://4mf81m04wehh3.doubao.link/app/app_17hpue26uuw | `F:\Daodao\版本清单_src\index.html` |

地址本身不会随版本变，**换的只是页面里的版本号和直链**。

## 五步走

1. **传包取直链**：`FileBatchUpload` 传 `F:\Daodao\道.exe` 与 `F:\Daodao\道.apk`，拿到两条 `aka.doubaocdn.com/s/xxx`。直链是一次性的，每次发版都要重新传。
2. **改下载页**（`引导页_src\index.html`）：`<html>` 上的 `data-ver` / `data-exe` / `data-apk` 三个属性都要换；正文的 `vbadge` 版本号、两端 MB、日期；两处 `data-bytes` 换成**真实字节数**（自动更新拿它比大小，错了会误判成没网或版本不符）。
3. **改清单页**（`版本清单_src\index.html`）：`<body data-ver>`、`v147`、两端 MB、发布日期、本次更新一栏写这版**实际**改了什么；两个 `<a>` 的 `data-exe`/`data-apk` 与 `href` 同换。
4. **发布**（PowerShell 工具，不加 `2>&1`）：
   ```powershell
   Set-Location -LiteralPath 'F:\Daodao\引导页_src'; lark-cli apps +deploy --file-path ./index.html --app-id app_17hnj8acgs2
   Set-Location -LiteralPath 'F:\Daodao\版本清单_src'; lark-cli apps +deploy --file-path ./index.html --app-id app_17hpue26uuw
   ```
   看返回 JSON 的 `ok`（不看 exit code）。拿到 `release_id` 后隔 15–20 秒 `+release-get --app-id … --release-id …`，**必须看到 `status=finished`**；报「发布任务已存在」就只查不重发。
5. **写三本账**：`自我状态\版本账本.json`（真用 + 检测的电脑/apk/页面/线上四处同号、落后 0）、`版本使用.json`（本版立项 ≥3 项，每项带验证日期 + 证据）、`网页更新记录.json`（追加 `PASS / 扣分 0`）。

## 验收口径
最后 `Invoke-WebRequest` 抓两页，正则 `data-ver="(\d+)"`，两处都等于新版本号才算上线。这一步只核对版本字符串，不作视觉判断。

## 踩过的坑
- 页面停在旧版很久没人发现：下载页曾停在 v62、清单页 v145，就是因为只发了包没重发页，账本里也没写「页面」这一项。现在**检测区块必须有「页面」字段**。
- 清单页源码和线上内容可能不同步（线上被别处覆盖过），改之前先看源码里 `data-ver`，改完以线上实测为准。
- `lark-cli` 的进度信息走 stderr，PowerShell 加 `2>&1` 会被当失败；加了 `--yes` 会报 unknown flag。
- 页面里的直链必须是 `aka.doubaocdn.com` 的真实链接，不能拿 `present_files` 回执或搜图 URL 顶替。
