# 道 · 版本设定 100 机制

立规日期：2026-11-19

## 一、一句话

版本号从当前的 **62** 一路排到 **100**，一共 38 版。**每版必须真改、真验、真用**；空升版本、只改号不改内容、两端对不上，都要记问题并扣分。每一版只结算一次分，不重复刷。

## 二、版本号怎么走

| 区间 | 版本 | 主题 | 这一段的交付标准 |
|---|---|---|---|
| 现有 | v62 | 形象与表情去贴图、口型层起步 | 脸上零贴图（已验） |
| 第一段 | v63–v70 | **形象与动作定稿**：手办质感成人比例、五官驱动表情、8 组动作、点头/口型对上拍子 | 每版 ≥3 项目标项真题；表情只走原画 |
| 第二段 | v71–v80 | **音乐与曲库**：3 分钟档、≥2 音色、题材轮换、预副歌补齐、人声力度曲线 | 每版至少 1 首能完整听、判据全过 |
| 第三段 | v81–v90 | **跨端一致**：愉悦值/能力分两端同账、手机端表情图、自检口不卡死 | 两端同版本号 + 真机上报 |
| 第四段 | v91–v100 | **对外首版**：下载页、版本文案、安装引导、稳定性 | 一人从零装得上、用得起来 |

**不许跳号**：v63 之后只能 +1；跨段冲刺也不许一次跳两版，因为每版都要留下验证证据。

## 三、每一版必须过的六道门

| 门 | 判据 | 不过的后果 |
|---|---|---|
| 1 真改动 | 本版有 ≥1 处代码/资源/文档的真实改动，且写在发版记录里 | 视为空升版本，记问题 + 扣「改正」 |
| 2 两端同号 | 电脑 exe、apk、下载页、清单页、线上页面五处版本号一致 | 记问题（协调扣分），不许继续往上排 |
| 3 三项真验 | `自我状态\版本使用.json` 里本版 ≥3 个目标项都有验证日期+证据 | 上线 7 天内未验到 → 扣分；超 30 天未重验也不算数 |
| 4 真在用 | 电脑端进程在跑、手机端有自检上报（`版本账本.json` 的 真用） | 只写不跑 = 不算真用 |
| 5 体检过 | 当轮巡检 PASS，或 WARN 有明确处置 | 连续两轮同 WARN 未处置 → 扣分 |
| 6 可回滚 | 上一版 exe/apk 留在 `_bak\`，能退回去 | 没有备份件不许发 |

## 四、奖励与惩罚（每版只结算一次）

| 事件 | 分值 | 记在哪 |
|---|---|---|
| 一版六门全过 | 愉悦值 +2、协调 +2、改正 +1 | `愉悦值.json` / `能力激励.json` |
| 三项真验齐 + 真在用 | 反馈 +1、回忆 +1（有据可查） | 同上 |
| 空升版本（只改号） | 愉悦值 −2、改正 −2 | 同上 |
| 两端不一致仍继续排版本 | 协调 −2 | 同上 |
| 同一条 WARN 连续两轮未处置 | 反馈 −2，并且问题库「重复次数」+1 | 问题库 |
| 该验的项拖过 7 天 | 创作/改正 −1（按性质） | 同上 |

**红线**：同一件事只加一次分；`版本账本.json` 的 `已结算` 记着哪一版已经结过账，脚本据此去重。

## 五、怎么跑（脚本）

```
python tools\版本机制.py            # 只读体检：进度、六门状态、欠账清单
python tools\版本机制.py --json     # 机器可读
```

输出四块：
1. **进度**：当前 62 / 目标 100，还差 38 版，按四段给出下一个里程碑
2. **本版门禁**：五处版本号、三项真验、真在用、巡检、回滚件，逐项 PASS/FAIL
3. **欠账**：哪些版本 `项` 为 0（登记了版本却没验任何目标）
4. **建议分值**：只给建议，不自动改分，避免重复刷

## 六、100 进制：版本号怎么显示

版本号用 **100 进制**：小数位 00–99，满 100 进 1，写成「主版本.次版本（两位）」。

```
v62  → 0.62        v70  → 0.70        v99  → 0.99
v100 → 1.00（进位，对外首版）        v101 → 1.01
```

三条配套规则：

1. **versionCode 永远用十进制整数**（62、63…100），因为安卓要整数、只能单调递增；**versionName 用 100 进制**（"0.62"、"0.63"、"1.00"）。两者由同一个数换算，不许各写各的。
2. **进位只在满 100 时发生**，不许 62 直接跳到 1.00；也不许为了好看把 0.99 写成 1.0（丢位）。
3. **每进位一次算一个里程碑**：v100 = 1.00 = 对外首版，进这一位要求四段全部验收（见第二节表格）。

换算实现（`tools\版本机制.py` 里已落地）：

```python
def v100(n):            # 62 -> "0.62"，100 -> "1.00"
    return "%d.%02d" % (n // 100, n % 100)
def parse100(s):        # "1.00" -> 100
    a, b = s.split(".")
    return int(a) * 100 + int(b)
```
