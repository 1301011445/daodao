# 道的能力激励与惩罚制度（v3，2026-11-18 口径重设）

一句话：**十项能力各拆成 2–3 个子项，每个子项都按"能做到什么程度"打分，分数只由脚本按文件事实算；涨得多奖励、跌得多惩罚，跌到 30 以下自动立"补短板"项。**

> v3 变更：v2 的公式是"一个数量×一个系数"（帧数×0.6、音色×4…），容易被"堆数量"糊弄，也看不出**质量**（例如母带只有 90 秒也按"1 首"给分）。v3 把每项拆成「量 / 覆盖率 / 新鲜度 / 根因」几类子项，权重有意设得比现状高：**能满分说明真做到位了，不是拿数量凑出来的**。
> 换公式当天不特批加分：仍按 `+min(3, 差÷5)` 一天一步往上走，避免"改个公式自己给自己发糖"。

数据来源全部是可重算的文件事实，没有一条靠"感觉"。

## 二、加/扣分规则（每天结算一次，多跑不重复）

- **奖励**：子项加权的证据分比当前分高 **≥5** → 加 `min(3, 差值÷5)`（至少 +1）。
- **惩罚**：证据分比当前分低 **≥5** → 扣 **1**，同一项 **7 天内最多罚一次**（防"越查越低"的假崩）。
- 差 1–4 分属"平稳"，不动；分数夹在 0–100。
- **和愉悦值联动**：十项变动合计写进愉悦值台账，单日最多 **±5**。

## 三、三条状态线

| 状态 | 条件 | 要求 |
|---|---|---|
| 补短板 | < 30 分 | 当天做一件能验证的小事，写进问题库 |
| 平稳 | 30–79 | 正常推进 |
| 奖励档 | ≥ 80 | 算强项，可支撑创作/推广 |

## 四、低能力自救（自动）

- **< 30 分立刻登记**；**< 45 分且连续 3 次结算不达标**也登记（`来源=低能力自救`，P2，固定 key `ability:能力名`）。
- 回到 **≥ 50 分**自动关；同 key 再掉回去 → **重新打开并累计复发**，吃复发重罚档。

## 五、谁检查、什么时候

- 每天：巡检跑 `tools\能力激励.py`，报告出【能力激励】段（旧分→新分、加减、状态、**子项明细**）。
- 结算幂等：`最后结算日` 记当天，重复跑只显示"今日已结算"。
- 改子项或权重：只改 `tools\能力激励.py` 与本文档两处，改完跑一次确认 `CAP_STATE=OK`。

## 六、防作弊（红线）

- 分数不许手改 `能力激励.json`，脚本每轮会按事实覆盖。
- 证据必须是文件/命令能复现的数字（帧、条、行、秒、份、毫秒）。
- 禁止"堆无效产物刷分"：词本要有对应曲子或用途；学习文档要有可读内容；**合格成品只认 170–200 秒的真母带**（90 秒那种不给分）。
- **一鱼两吃也不行**：同一个文件/产物只归一一个能力。乐理只算「学习」，不再给「创作」加分；创作看的是成品、半成品、词本和词曲配对。
- 惩罚被冷却挡住时，状态仍按证据分标"补短板"，不许把冷却当"没问题"。

## 七、程序与能力的对应

| 程序（巡检【各项程序】行） | 对应能力 | 看什么 |
|---|---|---|
| 桌面端 exe | 动作、反应 | 帧数与覆盖、自检口毫秒、渲染毛病 |
| 手机端 apk | 协调、动作 | versionCode 与电脑端、包内页面与源 |
| 网页（下载页/清单页） | 反馈、协调 | data-ver 跟上没有 |
| 定时任务 | 协调、改正 | 在册、跑得起来 |
| 音乐与创作 | 创作、学习 | 合格母带首数、判据、归档 |
| 愉悦值与问题库 | 反思、反馈 | 台账在记、问题真修 |

- 程序判 DOWN → 对应能力当天必然掉分；程序 OK 但能力仍 <45 → 说明该程序还有没暴露的短板，下一轮先补证据指标。


## 回忆能力（2026-11-19 加，第十一项）

定义：能不能把"以前发生过的事"原样取回来——上次聊过的话、做过的活、用户定过的偏好、账本里的历史、版本先后。

四维证据，各自独立计分，不重复加（同一件事不许给两项能力加分）：

| 维度 | 加 | 减 |
|---|---|---|
| 命中率：被问"上次/以前"能否定位到具体条目（文件+条目/行） | +2（能定位） | −2（答不出/只会说"好像有"） |
| 精确度：引用的旧事实与原文一致（时间/数字/路径） | +1（全对） | −3（张冠李戴、版本号或路径记错） |
| 新鲜度：旧结论被推翻后不再复用 | +1（用最新） | −2（拿过期结论当现状） |
| 可复查性：回忆结果落进文件（台账/memory/文档） | +2（已落盘） | 0（只在对话里说） |

台账：`自我状态\回忆台账.json`，用 `python tools\回忆.py ask "问句" 命中|部分|未命中 "来源" "明细"` 记；
同一问句 + 同一来源 24 小时内只记一条（严禁重复刷分）。

加重规则：同一个回忆错误第 2 次出现，罚分翻倍（−3 → −6）并在问题库留一条 Q；
第 3 次仍犯，直接标 P1 待处理。单次变动仍受 ±6 截断，与其余十项同口径。

落地检查：`tools\inspect_dao.py` 的 `cap_check` 会校验收敛——缺「回忆」项或证据为空即 WARN。
