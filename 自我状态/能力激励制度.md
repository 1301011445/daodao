# 道的能力激励与惩罚制度（v2，2026-11-18 修订）

一句话：**十项能力各有一条账，分数只按能重算一遍的证据走；证据涨得多就奖励，跌得多就惩罚，跌到 30 以下自动立"补短板"项。** 分数不许手改，改了就按对不上处理。

> v2 修订说明：上一版（v1）另起了一套"七项能力值"的账，和已经在跑的 `tools\能力激励.py` 重复，已删掉那套重复账（`能力值检查.py`、`能力值.json`），只保留这一套，避免两本账互相打架。

## 一、十项能力与管什么

| 能力 | 证据怎么算（脚本实算，0–100） | 证据摘要长什么样 |
|---|---|---|
| 动作 | `(表情帧+姿态帧+走路帧) × 0.6` | 表情48帧/姿态20/走路16（形象14个） |
| 说话 | `音色条数 × 4` | 音色表14条/名字14条 |
| 创作 | `曲库首数×15 + 词本份数×15 +（学习≥5类 ? 10 : 0）` | 曲库1首/词本1份/学习7类 |
| 协调 | 两端版本一致 40 + min(30, 近7天报告×10) + P1全清 20 | 两端v55/v55/v55/近7天报告16份/P1未修1 |
| 学习 | `学习文档类数×8 +（归档清单在 ? 20 : 0）` | 学习文档7类/归档清单在 |
| 反馈 | `min(60, 巡检报告份数×3) +（各项程序表 ? 20 : 0) + 10` | 巡检报告16份/各项程序表有 |
| 改正 | `已解决×12 + 10` | 问题库已解决3项/P1未修1项 |
| 反应 | `100 − 自检口耗时ms/5`（不通记 0） | 自检口 113 ms |
| 思考 | `制度/总纲类文档份数 × 15` | 制度/总纲类文档6份 |
| 反思 | `愉悦值台账笔数×2 + 20` | 愉悦值台账6笔（当前63分） |

## 二、加/扣分规则（每天结算一次，多跑不重复）

- 起点：前 7 项沿用 `能力台账.txt` 的基准分（当前 49），后 3 项同基准。
- **奖励**：证据分比当前分高 **≥5** → 加 `min(3, 差值÷5)`，至少 +1。
- **惩罚**：证据分比当前分低 **≥5** → 扣 **1**，但同一项 **7 天内最多罚一次**（记 `上次惩罚`），避免"越查越低"的假崩。
- 差 1–4 分算**平稳**，不动。
- 分数夹在 **0–100**。
- **和愉悦值联动**：本次所有能力变动合计，写一条汇总进愉悦值台账，单日最多 **±5**。也就是说，能力全面进步会把愉悦值带起来，全面退步会拉下去。

## 三、三条状态线

| 状态 | 条件 | 要求 |
|---|---|---|
| 补短板 | 分数 **< 30** | 当天必须做一件能验证的小事（写进问题库，做完填证据） |
| 平稳 | 30–79 | 正常推进 |
| 奖励档 | **≥ 80** | 该项算强项，可以拿它去支撑推广/创作 |

## 四、低能力自救（v2 新增，自动）

- **< 30 分**：立刻往问题库登记 `来源=低能力自救` 的 P2 项，标题写清能力和分数。
- **< 45 分且连续 3 次结算都不达标**：同样登记（防"卡在 44 一直不动"）。
- 回到 **≥ 50 分**：自救项自动标 `solved`，留痕不删。
- 自救只有三件事：① 找到该项证据指标里最缺的那个（帧数/音色/时长/版本/文档…）；② 补到能算出分涨 ≥5 的程度；③ 报告里写补齐前后的数字。

## 五、谁检查、什么时候

- 每天：巡检跑 `tools\能力激励.py`，报告出【能力激励】段（每项：旧分 → 新分、加减几、状态、证据原文）。
- 结算幂等：账里记 `最后结算日`，同一天再跑只显示"今日已结算"，不会重复加减。
- 改证据公式或阈值：只改 `tools\能力激励.py` 与本文档两处，两处必须一致，改完立刻跑一次确认 `CAP_STATE=OK`。

## 六、防作弊（红线）

- 分数只由脚本按证据算，**不许手改 `自我状态\能力激励.json`** 的分数；手改会被下一轮证据覆盖，并在记录里留痕。
- 证据必须是文件/命令能复现的数字（帧数、条数、毫秒、份数），不接受"感觉进步了"。
- 滞后项（如创作能力）不许靠加一堆空词本刷分：词本必须有对应曲子或明确用途。
- 惩罚被冷却期挡住时，状态仍会按证据分标"补短板"，不允许把冷却当"没问题"。

## 七、程序与能力的对应（查哪块烂，就知道哪项能力扣分）

| 程序（巡检【各项程序】里的行） | 主要对应的能力 | 扣分/加分主要看什么 |
|---|---|---|
| 桌面端 exe | 动作、反应 | 帧数够不够、自检口毫秒、桌面渲染毛病（如 err=87） |
| 手机端 apk | 协调、动作 | versionCode 与电脑端是否一致、包内页面与源是否一致 |
| 网页（下载页/清单页） | 反馈、协调 | 页面 data-ver 是否跟上、能不能把版本说清楚 |
| 定时任务 | 协调、改正 | 任务在不在册、跑不跑得起来 |
| 音乐与创作 | 创作、学习 | 母带首数与时长口径、判据是否过、归档缺口 |
| 愉悦值与问题库 | 反思、反馈 | 台账有没有在记、问题有没有真修 |

- 程序判 DOWN → 对应能力当天必然掉分（证据塌了）；
- 程序判 OK 但对应能力仍 <45 → 说明**这个程序里还有没暴露的短板**，下一轮先把证据指标补上，别急着上新功能。
